**Key findings**

1. **Ungrounded tool calls (Q5, error)**: 95 of 534 calculate_bmi examples (78 / 7 / 10 train/val/test) have gold arguments whose weight and height appear nowhere in the note, table or question. Training on them teaches argument hallucination; see P-012.
2. **Measurements only in the question (Q5)**: 67 BMI examples state weight/height only in the question, not in the note - the model must read the question as part of the input.
3. **BMI decision boundary (Q8)**: tool_call | weight+height both present: 439; tool_call | weight+height missing: 95; uncertain | weight+height missing: 148. Apart from the ungrounded tool_call rows, 'both measurements available' separates tool_call from uncertain perfectly.
4. **Imperial rounding (Q6)**: 51 inch heights do not round-trip to the gold cm value (max gap 0.126 cm); computing BMI from exactly converted values changes the result by +/-0.1 in 20 of 138 imperial examples. Evaluation uses source-precision-aware argument rules, not a universal tolerance (P-009).
5. **Stated BMIs are unreliable (Q7)**: 119 of 619 notes that state a BMI disagree with their own weight/height by > 0.5 (buckets: {'0.5-1': 39, '1-2': 33, '2-5': 30, '>=5': 17}).
6. **Arithmetic audit (Q10, heuristic)**: 0 candidate issues across 133 parsed equations and 389 'by D' amounts; 389 'by D' amounts verified. Flags require review; the checker does not establish the cause of a mismatch.
7. **External reference ranges (Q11)**: 46 extractive answers cite a standard reference range that is not in their input (value comes from the note text, table is a different panel).
8. **Micro sign vs Greek mu (Q13)**: 56 tool_call examples write µ (U+00B5) in question/answer but μ (U+03BC) in tool arguments.
9. **Overlap audit (Q3/Q18)**: Q3 flags=0, Q18 flags=0; max observed test-vs-train Jaccard 0.2. These checks do not prove absence of semantic or template leakage.
10. **Stretch B feasibility (Q19)**: 630 notes contain a medication pair covered by the reference; drug-pair keys are {'alphabetical': 32, 'non-alphabetical': 32} ordered, so lookup must be order-insensitive.
