## 3. Wave-1 results analysis

**Source.** `~/Downloads/outputs_9599.zip` and `reports_2425.zip` (RunPod RTX 4090, CUDA 13). They were extracted to `/tmp/wave1`; the repo's own `outputs/` still only holds the CPU smoke run.

**Runs.**
- Six candidates: raw lr 1e-4, raw lr 5e-5 and Q5-filtered lr 5e-5, each at epoch 1 and epoch 2.
- Selected: raw lr 1e-4 epoch 1, which was then evaluated once on test.
- Training took about 44 minutes (about 10 s per step), with peak VRAM 7.8 GB of 24. Eval used batch size 2.

**Findings.**
1. **The v1 scorer understated base and SFT alike**:
   - base extractive: 39% under v1, about 90%+ in reality;
   - SFT numeric: 60% under v1, about 80% in reality.
2. **78 Q5 train records teach confident argument invention.** They have no weight or height, yet gold calls BMI.
   - The raw SFT calls on those records with p ≈ 0.99, repeatedly using 178.5 cm.
   - Base and the Q5-filtered model abstain (p ≈ 0).
   - v1 and the wave-1 selection rule could not see this.
3. **The call decision is fully separable after SFT** (AUROC 1.0). Remaining tool errors are imperial rounding of 0.1–0.2 (test only) and one missing reported result.
4. **Numeric is the main real weakness**: wrong analyte in "most" questions, reversed direction, ranges from memory rather than the table, incomplete lists.
5. **Hyperparameters.**
   - lr 1e-4 beats 5e-5: +0.034 paired CI [0.007, 0.066].
   - Epoch 1 vs epoch 2 is noise.
   - Loss was still falling at epoch 2.
   - Q5 filtering has no cost on grounded records.

**Proposed wave-2 priorities.** Scorer v2 (done, below), Q5-filtered at lr 1e-4, extra seeds, lr 2e-4 with a larger micro-batch, relabelling Q5 records as uncertain, numeric-focused changes.

## 5. Scorer v2.0 → v2.1 (implemented)

**Files (all new; nothing existing was modified except `README.md` in step 1):**

| File | Contents |
|---|---|
| `src/clinqa/scorer_v2.py` | about 1,050 lines |
| `scripts/score_v2.py` | CPU rescoring of saved trajectories, v1 vs v2 tables |
| `scripts/scorer_v2_gold_check.py` | gold self-check |
| `scripts/scorer_v2_agreement.py` | agreement with the adjudicated sets |
| `tests/test_scorer_v2.py` | 16 regression fixtures, one per failure mode |
| `docs/SCORER_V2.md` | design |
| `reports/scorer_v2/` | keys, scored files, summaries, adjudication packets and labels, hashes, `VALIDATION.md` |

**Process:**

1. **MedCalc-style answer keys**, computed from input facts (table, question, note) before any prediction is read. Type-specific tolerances; pass or fail only.
2. **Gold self-check on train/val**, from 90.2% to 98.6% / 100%. Fixes:
   - question facts and note facts;
   - domain guards;
   - "above normal";
   - percentage points;
   - pronoun coreference;
   - hypotheticals;
   - blanket statements;
   - range-position phrases;
   - clause subject carry-over;
   - an `re.match` `^`-anchor bug;
   - Q6 rounding in the Q5 grounding check.
3. **Policy:** unrecognised explanatory clauses are not scored when any structured check exists; the text fallback is used only when nothing structured applies.
4. **Development adjudication** (val, 120 items). Rater B was discarded for templated labelling and replaced by four strict raters. After fixes, v2.0 reached 99.2% on this set.
5. **v2.0 frozen** (sha256), then **holdout 1** on test (120 items): **76.7%, κ 0.48**. This showed overfitting to the development set, and is reported as is.
6. **v2.1**: general fixes from the holdout-1 errors:
   - last assertion wins;
   - explicit thresholds and ranges from the question;
   - stage numbers and digits inside words are never thresholds;
   - yes/no direction;
   - "closest" and "midpoint" checks;
   - clause-level hypotheticals;
   - singular "which other";
   - unhedged-safety detection for uncertain;
   - tool status consistency;
   - Markdown and newline handling;
   - blanket-statement scope;
   - adjective binding;
   - modifier uses ("creatinine production");
   - lab pools from the note.

   Result: 95.0% on holdout 1 (now a development set) and 100% on the first development set.
